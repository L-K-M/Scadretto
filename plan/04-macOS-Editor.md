# macOS document editor and interaction

Build the application around `NSDocumentController`, one `ScadrettoDocument` subclass, a document window controller and native menus. Use an AppKit split view for the editor, viewport and inspector. Prefer AppKit-native controls (`NSTextField`, `NSPopUpButton`, `NSButton`) for interactive inspector fields: numeric entry must commit through the document undo manager like any other edit, and `NSHostingView` can break the first-responder chain, swallow Enter/Escape, register its own undo and disturb IME composition. Host SwiftUI only for read-only display content, and only after verifying first-responder behavior and the document undo stack. Use an `MTKView` for geometry. Compile shaders into a `.metallib` at build time and ship that; runtime source compilation is a development convenience, not the shipped path — it would spend launch time on the Metal compiler and distribute source the release doesn't need. [Apple document architecture](https://developer.apple.com/documentation/appkit/nsdocument) · [MetalKit view](https://developer.apple.com/documentation/metalkit/mtkview)

## Window and commands

| Surface | Required behavior |
|---|---|
| Source editor | Plain monospaced text, line numbers, syntax colors, find and replace through the standard find bar, with Replace All's per-match replacements batched into one document transaction with disjoint edits and one undo entry, diagnostics, jump-to-range, and selection synchronized on explicit navigation. Disable smart quotes, smart dashes, automatic text replacement, autocorrection, continuous spell checking, grammar checking and rich text (plain-text storage only), so the input system never rewrites code bytes. Keep normal typing focus when the preview refreshes. |
| Viewport | Shaded solid, orbit, pan, zoom, frame model and frame selection. Display local or world axes as applicable, selected outline, cutter overlay and editable handles. Preserve camera across reevaluations. |
| Inspector | Selection breadcrumb, source location, authored expression, evaluated value, available edit scopes, affected occurrence count and reason for any disabled edit. Support numeric entry with Enter to commit and Escape to cancel. |
| Instance outline | Display expanded module calls, loops, primitives and boolean operands. Distinguish the selected occurrence from the shared definition. Virtualize large subtrees and let users select enclosed operands. |
| Console | Show the `echo()` output, warnings and `assert` failures of the latest completed evaluation in order, including a failed one. Label whether the geometry on screen came from the same evaluation. Mark the console out of date while a newer evaluation is pending. Each message with a span jumps to its file and range. Text is selectable and copyable, with a severity filter. Show a visible notice when the worker truncated the capture, including the dropped count. |
| Status area | Report evaluating, ready, valid empty model, preview out of date, cancelled, source diagnostics and worker failures. Make the current failure and source location reachable with the keyboard. |
| File and Edit menus | New, Open, Save, Save As or Duplicate as appropriate for native document mode, Revert, Undo, Redo, Find, and Find and Replace. Register `.scad` as an editable document type. Keep Finder and drag-to-open working. |
| View and Model menus | Toggle editor/inspector/outline, standard views (top, bottom, left, right, front, back and diagonal) with keyboard shortcuts, each defined by an eye direction and up vector in the Z-up world, such as front looking along +Y and top looking along -Z with +Y up, perspective or orthographic projection, Show Edges and Show Axes toggles as upstream offers them, frame all, frame selection, reevaluate, cancel evaluation, reveal source and choose an edit target. Provide accessible alternatives to viewport gestures. |

A second document gets separate selections, worker requests, camera, diagnostics and undo history. Windows belonging to the same `NSDocument` share the one source buffer, transaction path and undo history. An edit committed in either window updates text, byte/UTF-16 index, syntax ranges and inspector state in both, and registers exactly one undo item. Re-anchor or clear the other window's selection and write-back handles by source anchor and call path rather than by index; each window keeps its own camera. During input composition in either window, defer graphical commits in both. Store window presentation preferences separately from the `.scad` bytes.

## Code editing and diagnostics

1. Build `NSTextView` inside a scroll view. Choose TextKit 1 or TextKit 2 explicitly in M1 and record the decision. On macOS 13 and later, AppKit creates `NSTextView` with TextKit 2 by default. The first time any code reads its `layoutManager`, the view falls back to TextKit 1 for the rest of its life. Typical line-number ruler code does exactly that, and the switch changes layout and performance mid-session. With TextKit 2, draw line numbers and diagnostic markers from `textLayoutManager` layout fragments. Fail debug builds when the text view posts `NSTextView.willSwitchToNSLayoutManagerNotification`. With TextKit 1, create the view with `NSTextView(usingTextLayoutManager: false)` from the start. Measure typing and scrolling in a generated 20,000-line file before deciding. Use a delegate or text-storage adapter to convert actual replacements to byte patches. Group typing using native editing conventions. Choose one registration route for typing and one for programmatic transactions, both backed by the document undo manager. Guard against delegate reentry when mirroring a patch.
2. Apply syntax colors as presentation attributes. Isolate highlighting from the undo stack and edited state. Preserve marked text for input methods, selection and scrolling. Never change attributes inside the marked range while composing; skip that range for syntax colors and color it once the composition ends. Resolve diagnostics through the byte/UTF-16 converter. Never reposition the insertion point just because a background render finished.
3. Connect caret or an explicit “Reveal in Model” action to the nearest syntax call and current scene. When one statement generates several instances, highlight the group and allow navigation to an individual instance. On a viewport pick, highlight the corresponding code expression without taking keyboard focus unless “Reveal in Source” was invoked.
4. Keep editing, saving and undo functional while the last-good preview is stale. Disable source-writing handles until the current key has valid geometry and bindings. For an empty valid model, clear the old solid and retain navigation for surviving source diagnostics. If no valid snapshot has ever existed, show a blank viewport with the actionable diagnostic.

## Viewport gesture contract

| Gesture | Feedback during gesture | Commit |
|---|---|---|
| Orbit / pan / zoom | Camera changes, rendered model and overlays track it | Camera state only |
| Click a visible surface | Highlight selected occurrence, code range, scope and related instances | Selection only |
| Click an ambiguous edge | Show a short ordered list of candidate operands plus their source locations | Select exactly the chosen candidate |
| Select an outline operand | Show ghost geometry, including material removed by a difference | Enable equivalent inspector controls |
| Drag a supported handle | Show axis, origin, current dimension or delta, target expression and affected instances | Apply one verified patch on mouse-up |
| Escape, zero delta or change of document revision | Restore the last accepted drawing and label | No source mutation |

Start with click to select, ordinary drag on an explicit handle, background drag to orbit, right-drag to pan as upstream OpenSCAD does, and Shift-drag to pan for one-button input. A right-click without motion opens the context menu. Map scrolling by event precision and phase, because AppKit does not report the device. Scrolling without precise deltas, as from a mouse wheel, zooms about the point under the cursor. Precise scrolling with gesture phases, as from a trackpad or Magic Mouse, orbits; with Shift it pans. Offer a preference that swaps orbit and pan for background drag, precise scrolling and their Shift variants. Right-drag keeps panning, and a motionless right-click opens the context menu in either mode. Pinch zooms about the cursor. In orthographic view, zooming changes the view width about the cursor instead of moving the camera. Ignore momentum scroll events that arrive after a handle drag begins. Disambiguate a click from a drag with a small movement threshold. Respect backing scale when converting window coordinates to drawable pixels. Convert between AppKit's view coordinates and Metal's viewport convention exactly once. Test on a Retina display and with a resized viewport. The backing scale can also change without a resize, when the window moves between a Retina and a non-Retina display or the display mode changes. Handle `viewDidChangeBackingProperties()`: confirm the drawable size follows the new scale rather than relying on `MTKView`'s automatic resizing, which is documented for size changes, then rebuild the projection and every cached pick transform from the new drawable size. Test a pick on the third bore after moving the window between displays of different scale. A keyboard user must be able to reach the same property by outline and inspector alone.

Give handle hits priority over object hits only while the handle is visible and a compatible operation is selected. Orient drag handles to their advertised frame. Use a projected axis or an axis-aligned drag plane; when ill-conditioned, show numeric entry. Honor the visible snap increment from the app preferences (model units, default off, applied to the committed value as defined in [file 02](02-Source-and-Edits.md)). Recalculate the candidate value from mouse-down baseline each frame so snapping and round-trip motion do not accumulate floating-point error.

Keep the presented frame’s scene identity, view/projection matrices and drawable-to-view mapping together. Use those values for hit testing, including handle hits. A ready BVH or submitted frame may belong to a scene the user has yet to see. If the presented scene is no longer current or its coordinate mapping no longer describes the view, defer selection until the replacement is visible and require a fresh click. Validate an asynchronous hit against its frame and scene before exposing a writable target. Treat IDs as local to that successful evaluation, including repeated runs with an identical source key.

Test with two scenes that assign the same instance ID to different cutters. Hold presentation of the second frame after its scene is accepted and click the first cutter’s pixel. The click must never select or arm the second cutter. Present the replacement, resize and orbit, then verify a fresh click at a projected bore wall selects the visible occurrence.

### Example interaction

Click the inner cylindrical wall of hole three on the fixture. The breadcrumb identifies the third iteration, `mounting_hole` and `cylinder`. The inspector shows `Diameter 4`, the expression chain `d ← hole_d`, and `Shared parameter · 4 cutters`. Selecting that shared target lights up all four cutters. Drag its radius handle outward 0.5 model units or type a diameter of 5. The overlay reports diameter 5. Releasing changes only `hole_d = 4;` to `hole_d = 5;`. The ordinary source editor shows the edited declaration. Undo restores diameter 4 and all four bores.

Use the same feedback for a local offset. A cheap moving outline or operand proxy is sufficient while dragging. Draw unchanged booleans in the existing shaded result and identify the moving overlay as a preview; update the actual boolean solid when the committed evaluation returns.

## Files, libraries and external changes

- Declare the `.scad` document type in `Info.plist`: a document type with `CFBundleTypeRole` `Editor`, `LSHandlerRank` `Owner` (or `Alternate` when another application owns the type), and a type identifier conforming to `public.source-code` (which itself conforms to `public.plain-text`). Export that identifier with `UTExportedTypeDeclarations` only when this app owns it; if an installed app already declares the `.scad` type, import it with `UTImportedTypeDeclarations` instead and do not claim ownership. Register the type with Launch Services and verify Finder double-click, drag-to-open and `open -a` all reach the app. Support opening read-only files for inspection, with Save As to create a writable copy.
- Use coordinated document reading/writing and native safe-save behavior. Snapshot the bytes for saving. Mark only the saved revision as acknowledged when a newer edit arrived during the write. Integrate with native edited-state and autosave APIs, and test Save As to another directory.
- Track both a disk baseline digest and current unsaved bytes. When a clean main file changes externally, reload and reevaluate. For a dirty file, keep local bytes and present **Compare**, **Keep Editing**, and **Reload from Disk** with an explicit discard decision. After Keep Editing, preserve the conflict and make overwrite versus Save As explicit at save. Do not let autosave overwrite the external version while conflict is pending. Avoid reacting to the app's own coordinated saves as external conflicts.
- For an existing destination, carry the expected on-disk version into the coordinated write. Recheck its presence, identity and digest inside the write accessor before replacing it. If it differs, exit through the conflict flow and keep the local edit dirty. Bind an explicit overwrite to the version the user reviewed and repeat the check if another writer changes it. Advance the disk baseline only after a successful write.
- Treat a main file that disappears on disk as an external removal, not as an empty or recreated file. Keep the in-memory bytes, mark the document as having no acknowledged disk baseline, and require an explicit Save As to choose a new location; do not silently recreate the old path on the next autosave. A rename or move by another writer updates the logical URL only after the user accepts the new location; until then the document behaves as dirty with unsaved changes.
- Observe resolved dependency files and their parent directories to catch atomic replacements and deleted/recreated files. Debounce duplicate notifications. Track an unresolved include or asset's candidate parent path so creating it can recover the preview. Record resource roots on each evaluation. A changed dependency invalidates current write-back handles immediately.
- Edit one active file per transaction in v1. Navigate to a dependency in a separate editor document when requested. Evaluate referring documents against their saved dependencies; label this behavior in the UI if an included file has unsaved edits elsewhere. Saving the dependency triggers reevaluation of affected parents.
- When the helper fails to launch or load a library, offer logs and Retry Preview. Always preserve the source. Treat the helper as a child process of a non-sandboxed, directly distributed application in this plan. Its process boundary gives crash isolation; any later sandboxed distribution needs its own file-access design.

Exercise the save race with a controlled write barrier. Dirty the main file, schedule autosave, replace the on-disk file from another coordinated writer before autosave gets access, and hold back the change notification. Resume autosave. Verify the external replacement survives, local edits stay available for Compare or Save As, and a second external replacement after overwrite confirmation requires a fresh decision.

## Accessibility and native acceptance

Give controls accessible labels that include the property and scope, expose selected/disabled state, and announce render failures concisely. Pair colors with outlines, labels or glyphs. Use dynamic system colors, visible keyboard focus and a tab order through source, outline and inspector. Add accessible identifiers for UI tests covering every surface in the table above, including `sourceEditor`, `viewport`, `sceneOutline`, `inspector`, `targetScope`, `diameterField`, `candidateList`, `console` for the ambiguous-pick list, `renderStatus` and `statusArea`. Make the model and selection accessible without sight: publish a concise textual summary of the current selection (breadcrumb, property, scope and evaluated value) and of scene state changes (evaluating, completed, failed, stale) through the accessibility channel, and keep it reachable from the inspector. Announce a committed edit's scope and affected-instance count. Give the viewport an accessible description that names the presented scene and its bounds, and let VoiceOver move from the outline to the inspector without entering the Metal view. Check VoiceOver navigation, dark mode, high contrast, split-view resizing, multiple windows and native Save/Undo menu titles on a real Mac.
