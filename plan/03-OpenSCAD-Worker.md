# OpenSCAD worker, evaluation trace and geometry

## Build the smallest integration that proves the design

Use a source-pinned headless OpenSCAD executable as a separate process. Build two variants from the same revision and dependencies: an untouched reference CLI for CI and a Scadretto worker carrying the trace patch. The worker is the geometry backend for the shipped app. The reference CLI is a development and verification tool. Upstream documents headless and no-OpenGL CMake options. Inspect the chosen revision's CMake settings before freezing flags and backend. [Upstream CMake](https://github.com/openscad/openscad/blob/master/CMakeLists.txt) · [Command-line usage](https://en.wikibooks.org/wiki/OpenSCAD_User_Manual/Using_OpenSCAD_in_a_command_line_environment)

The trace hooks must preserve geometry, diagnostics and evaluation success or failure across the fixture suite. Compare against the unmodified CLI in the same mode. Test the worker protocol’s own exit conventions separately.

In M0, look for the actual parser location record, expression evaluation, module and builtin argument binding, control-flow expansion, transformation nodes, dependency resolution and final geometry export in the pinned tree. Record source paths and symbols in `Docs/Decisions/engine-spike.md`. Add narrow observation hooks and a new worker entry point in the patched build. The protocol below is an API for Scadretto to implement. Stock `.ast`, `.csg` or STL export does not supply this contract.

### Spike pass conditions

- Evaluate in-memory main-file contents at a real logical path. A sibling include and nested relative asset resolve from the same locations as in the reference build.
- Determine whether the pinned engine accepts a leading UTF-8 BOM on the main file. File 02 requires preserving one on open and save; if the engine's lexer rejects it or counts columns from a different origin, strip the BOM at the worker's input boundary and offset-adjust every reported source span — the same adapter rule the editor applies to its own parser. Record the observed behavior in `Docs/Decisions/engine-spike.md`.
- Evaluate the plate once and return one base plus four cutter occurrences with their four iteration values, the call site, the cylinder's source span, the numeric `d` value and the chain back to `hole_d`.
- Export a final mesh with the same bounds and volume as the reference. Select the cylindrical wall of the third hole and resolve it to the correct cutter. Capture the candidate list for a click exactly on a rim.
- If face ancestry does not survive the pinned boolean backend, implement the surface-hit comparison below and prove it on the fixture. If a trace hook cannot expose resolved argument bindings, instrument the binding step. Do not infer shared parameters from equal values or manufacture source IDs from mesh order.

## Version 1 transport

For v1, start one child per evaluation with `Process` and a private job directory. This gives cancellation by terminating the child, including while inside a long native boolean. Keep the wire contract transport-independent for later worker reuse. Measure cold spawn plus engine initialization at M0 — dyld, C++ runtime setup, bundled resource loading — and record it against the commit-to-frame budget in file 06. If measurements miss the target because of startup, prototype worker reuse as a separate decision and repeat the cancellation, process-isolation and clean-state tests before adopting it. Use direct executable URLs and argv entries. Resolve paths from the app bundle. Drain stdout/stderr concurrently and bound diagnostic output. Protocol data is exchanged through files; stdout and stderr are logs.

Launch the worker with an explicit environment: system `PATH`, app-owned home, private job temporary directory, UTF-8 character handling and locale-independent numeric formatting. Pass library roots in the request. Bundle a licensed, pinned font set and fontconfig configuration. Share its versioned cache across jobs and serialize first use. A non-text model must not wait for font discovery. Use the same font inputs for reference renders. A reference-only `OPENSCADPATH` conveys the request’s ordered roots to the stock CLI.

Proposed invocation for the patched executable:

```text
scadretto-engine --scadretto-job /absolute/job/request.json
```

| Item | Required contents |
|---|---|
| `request.json` | `protocolVersion`, `requestID`, `EvaluationKey`, logical main URL, untitled base directory when applicable, relative path to main UTF-8 snapshot, ordered permitted library and resource roots, the `$preview` evaluation mode to run, selected geometry backend/options and expected worker build. The worker verifies that the resolution inputs match the key's digest. |
| `main.scad` | Exact unsaved source bytes for this job. Resolve paths and report diagnostics against the logical URL in the request. |
| `result.json` | Echoed protocol, request ID, key, build SHA, status (`ok`, `error`), outcome detail (including unsupported dimension), file table with digests, diagnostics and bounded console messages on both success and failure, observed dependencies, scene tables and payload descriptors |
| `mesh.bin` | Versioned final vertex and index buffers. Optional triangle-to-instance table has an explicit unknown value. |
| `operands.bin` | Pickable or highlightable operand meshes and transforms, with per-range descriptors. Identical local meshes may share storage across instances. |

The request names the `$preview` evaluation mode explicitly rather than an ambiguous "preview" flag: it is the boolean the engine evaluates the program under, and the reference CLI comparison in file 06 must run the same mode — a program branching on `$preview` produces different geometry under each. In v1 the authoritative scene uses final-render semantics, so requests send `$preview = false`.

The parent creates the job directory with private permissions. The child writes payloads first, closes them, writes a temporary manifest and atomically renames it to `result.json` last. On success exit 0, including for valid empty geometry. On a model error, write an error manifest then exit 1. The error manifest includes every dependency observed before failure, the attempted unresolved paths where known, and diagnostic source spans when available; the parent keeps watching them so fixing a missing file can trigger reevaluation without a source edit. Distinguish signal, timeout, memory limit, protocol mismatch and internal exit separately. Record timeout, cancellation or memory pressure before signaling the child. Report that initiating reason when reaping it. Classify an unexpected signal as a crash. Parent accepts only a matching, fully validated result after child exit. Matching means the echoed protocol version, request ID and key equal the request, and the echoed build SHA equals the SHA of the bundled worker named by the request's expected worker build. A worker that receives an unsupported protocol version writes a protocol-mismatch error manifest and exits nonzero without evaluating. A build SHA that differs from the expected worker build is a packaging failure. Its spans and bindings are never trusted, even when the manifest is otherwise valid. Accept only exit 0 with `ok` or exit 1 with a validated error manifest describing a model error or unsupported input. A missing, partial or contradictory manifest, signal, or other exit is a worker failure. Classify a valid top-level 2D program as unsupported for the 3D viewport, with a clear diagnostic, distinct from syntax failure and valid empty 3D geometry. Make protocol mismatch a visible development or packaging error.

The parent schedules at most one active job and one latest pending request per document, with an app-wide bounded queue. A newer request supersedes older work. Send termination, allow a short grace period, then force termination of that child if necessary; always reap it. Release job files after decoder/GPU users have relinquished any mapped data. On document close cancel queued and active work. macOS does not end child processes when their parent exits, so a crash or force quit would leave workers running inside long booleans. Connect each child's standard input to a pipe whose write end only the app holds, marked close-on-exec so no other child inherits it. The worker watches standard input on a dedicated thread and terminates on end-of-file with `_exit`, without waiting for the evaluation thread. The worker starts no processes of its own, so terminating it stops all of its work. On normal quit, terminate and reap every child with a short bounded wait before the app exits. Use a private per-app-session directory with an exclusive lifetime lock. On launch, reclaim only abandoned sessions after acquiring their lock. The worker must disconnect on parent EOF even during a long native operation. Make the first version's timeout configurable for slow valid models, with a visible cancel control. Never reapply an old result after user cancellation.

Monitor each child’s physical footprint from the parent. Record the peak sample and terminate a child exceeding the configured budget. Under critical system pressure, pause new dispatches and terminate active jobs as needed. Distinguish pressure from a per-job budget failure and keep source and undo available. Sampling is best-effort: budget headroom across concurrent children, measure overshoot and report termination latency.

Limit output file size in the child, and cap manifest size, record counts, diagnostics, payload bytes and decoded allocations before reading or mapping untrusted output. Fail the job and reap its worker when a limit is exceeded.

## Snapshot and geometry conventions

For the first golden protocol pair, use a request for `cube(2);` and a successful response with one file, one executed cube and one mesh. Give the JSON keys fixed spellings in `Engine/protocol/`. Represent byte offsets as integers, digests as lowercase SHA-256 hex, file identifiers and instance identifiers as distinct integer domains, and versions as integers. Use paths relative to the private job directory for binary payloads. Open payloads relative to a descriptor for the private job directory after child exit. Reject absolute paths, parent components, symlinks and non-regular files. Check size and decode from the opened descriptor. Include traversal and symlink cases in decoder tests. The main model's logical URL and user library roots are deliberately separate inputs. A second golden response should report invalid source with no mesh. A third pair, for the mounting plate, covers the trace contract itself: parent links, the four iteration bindings, the cylinder's `PropertyRecord` and its binding chain to `hole_d`, the difference's operand roles, the four cutters' operand mesh references, which may share storage when the implementation caches identical local meshes, and the triangle-owner table when the backend supplies one. Decode all three from Swift and validate them against the worker's schema in CI. `verify-engine` also compares the worker's actual output for each request with its golden response semantically: it canonicalizes request-local IDs and unordered tables. Preserve ordered children, binding chains, console sequence and boolean roles. Fix the expected trace and owner availability for the chosen pin. Compare resolved operand geometry regardless of storage sharing and validate binary layouts separately.

Hash the raw snapshot bytes for the main file and each dependency before any lexer adaptation, including a BOM. File lengths and all emitted spans use those same raw coordinates. Verify a BOM fixture’s SHA-256, byte length and post-adapter token ranges from the parent. Dependencies are every file the evaluation reads, not only `include`, `use` and `import()` targets: `surface()` reads a PNG or DAT heightmap, `dxf_dim()` and `dxf_cross()` read a DXF file, and `text()` reads the font files fontconfig resolves. Report each with its kind so the parent watches it and a change invalidates the scene. If a watched file changed while a job was running, reject the result and schedule the latest snapshot; install watchers and check the newly discovered dependency baselines before publishing the first result. Use a new job token for an explicit retry or cancellation even when the source key is unchanged, so a cancelled child cannot win against its replacement.

Use explicit versioned formats with fixed-width little-endian fields and IEEE floating-point values. Store source/evaluation metadata and affine transforms in double precision. Specify right-handed axes, Z up, 4×4 column-major matrices, column vectors, `world = parent × local × point`. Shared operand vertices are local; final mesh vertices are world coordinates. Carry final world-space positions as float64 on the wire and through CPU bounds and BVH construction. Subtract a double-precision render origin before converting final positions to GPU floats. Apply the same origin to operand transforms, camera and overlays so the visible and pickable surfaces coincide. Normals use the inverse-transpose transform with appropriate treatment of reflections.

Mesh descriptors declare byte offsets, counts, stride, scalar types, triangle winding and bounding box. Use packed `float64 xyz` for final positions (24-byte stride). Local operand positions may use `float32 xyz` when their precision suffices. Use `uint32` triangle indices and optional `uint32` triangle owner IDs. Reserve `0xffffffff` for unknown ownership and exclude it from the valid instance ID domain. Derive face normals from triangles for the first release. A missing owner table is distinct from a table assigning zero to all triangles. The decoder bounds-checks counts and multiplication, indices, offsets, file length, finite coordinates/transforms, and acyclic parent links before allocating or indexing. Protocol tests cover zero triangles, bad ranges, overflow, unknown fields, absolute paths, `..` traversal and symlink escape from the job directory. Unknown optional fields may be ignored; incompatible versions and unknown required enum values fail cleanly. Validate every owner and parent ID, operand payload range and source span against its own result tables and lengths.

Round-trip a synthetic unit-cube mesh translated to X = 100000000 through the binary encoder and Swift decoder. Require distinct X bounds of 100000000 and 100000001 and a hit at the latter from a ray starting at (100000002, 0.5, 0.5) looking along −X. Frame the cube and check the rebased GPU vertices retain unit width and its selection overlay aligns.

### Search-path dependencies

For each ordered file lookup, report the requesting file, lookup name, candidates tested before the first success and the chosen logical path. An absent higher-priority candidate is a dependency of a successful result. Watch for its creation, using the nearest existing ancestor when directories are missing. Install watches and recheck the winning path and digest before publishing. A different winner invalidates the generation even if both copies contain identical bytes, since navigation and nested imports depend on the location.

In a fixture with two ordered library roots, place `part.scad` only in the fallback root. Once its cube is visible, create a preferred copy defining a sphere. Require the sphere and its source location without touching the main file or fallback. Remove the preferred copy and require the original cube and location again.

## Trace contract

| Record | Required information |
|---|---|
| `FileRecord` | Logical path, canonical resolved URL if on disk, content digest and byte length of the consumed bytes, kind (main, `include`, `use`, `import()` asset, `surface()` heightmap in PNG or DAT form, DXF read by `dxf_dim()` or `dxf_cross()`, font file) and writability in this document |
| `InstanceRecord` | Request-local ID, parent ID, operator or module name, call span and definition span when known, evaluation path with iteration bindings, local/world transform, local bounds, nearest editable authoring call, operand mesh reference when available |
| `PropertyRecord` | Display semantic such as diameter, evaluated numeric value and unit, originally supplied arguments, the supplied argument span that bound each formal or `default`, superseded and unbound arguments with their warnings, resolved formal, token/expression span, definition and binding chain when observed |
| `OperationRecord` | Ordered child IDs for union, difference and intersection. Store operand role relative to its parent; a single “negative” flag does not encode nested differences. |
| `DependencyEdge` | From a resolved declaration or call-site argument to a currently executed property/instance. Track consumers conservatively; unknown impact must be displayed as unknown. |
| `Diagnostic` | Severity, message, file and optional byte span, optional call path, evaluation key |
| `ConsoleMessage` | Ordered `echo()` output and engine messages: upstream's formatted text, including its group prefix and location suffix, the upstream message group (echo, warning, error, trace, deprecated, parser, font, export and the others it defines), file, optional byte span and call path. Bound the count and total bytes; when a bound is reached, reserve space within both caps for a fatal diagnostic and a truncation count. Preserve retained messages in order. |

Capture console output through the engine's message logging hook in the patched worker and write it into `result.json`, including for a failed evaluation. Do not parse stdout or stderr for it. The reference CLI writes the parsing and instantiation messages, which include `echo()` and `assert` output, with `-o <file>.echo`. That export skips geometry evaluation, so compare it with the worker's messages up to the start of geometry evaluation, and check messages raised during geometry evaluation against golden files.

Normalize diagnostics from engine evaluation events rather than scraping stdout or stderr. Map each engine severity to one protocol severity (`error`, `warning`, `deprecated` or `unknown`), attach file and byte span when reported, and keep the call path that produced it. De-duplicate repeated messages with the same text, severity, file, span and call path; report a suppressed repeat count instead of flooding the status area or the manifest. A warning-only evaluation can publish geometry. Continue to enforce per-binding eligibility, including warnings for ambiguous arguments.

Collect provenance per occurrence, even when geometry evaluation uses a cached local mesh. Each loop iteration gets its own path and transform. Two equal cylinders can share vertex buffers, but each keeps a distinct runtime ID and parameter environment. Preserve include/use boundaries and original files for definition navigation. Treat imported assets or unsupported operators as opaque nodes with bounds and limited metadata.

Keep a scoped binding stack while evaluating module calls, loops, `let` and assignments. Record the actual file and scope used for caller-supplied arguments, children and definition-site defaults. Preserve dynamic lookup of special variables. Verify these distinctions with the pinned evaluator. A child passed through `children()` is authored at the caller's child statement, which can be in another file than the `children()` call; record that statement as its call span. Capture the evaluated argument → formal parameter → resolved declaration chain for supported scalar slots. Mark opaque arithmetic as an expression boundary unless a specific edit rule handles it. Track control dependencies when provable or mark the impact set partial. Keep the stock evaluator in charge of scoping, defaults, special variables and evaluation order. Never re-run random or time-dependent expressions merely to collect trace information.

## Picking a boolean result

1. Raycast the final visible surface, using a CPU BVH for v1. Build the ray from the active projection; an orthographic view uses rays parallel to the view direction, with each origin computed by mapping the cursor through the same view, projection and viewport transform used to render, so the pick lands on the drawn pixel. Return a world hit, triangle and normal. If the backend has a proven unique primitive ancestry for the triangle, use it and follow the instance chain to candidate authoring scopes.
2. Otherwise intersect candidate operand meshes around the *same world hit*, narrowing by transformed bounds, surface distance and normal alignment. Account for inverted cutter normals, nonuniform transforms and reflected winding. Document a scene-scaled distance tolerance with a floor and a cap; test small solids and close parallel walls. Matching the front face of a cutter somewhere else on the ray is insufficient.
3. Offer multiple candidates for coincident surfaces, rims and ambiguous operation paths. If no reliable owner exists, keep the result selected and offer the outline or operand-isolation mode. The outline selects an exact executed instance independently of triangle ancestry.
4. Selecting a cutter reveals a translucent operand and the subtracting operation. Selecting a shared declaration highlights all proven dependent occurrences. Render helpers, ghosts and gizmos in a separate pass so they cannot corrupt final-surface picks.

### Performance fallback

Cache local primitive buffers per scene, build BVHs off the main thread, instance repeated operands and load detailed overlay meshes on demand for expensive subtrees. Return explicit availability if budgets are exceeded. A large model can still render when fine picking for a branch must use the outline. An opaque preview is acceptable for unsupported constructions; the plate's through-hole wall must be pickable in the normal shaded view for release.
